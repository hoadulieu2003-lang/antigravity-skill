# Product and UI delivery

- Convert approved jobs, flows, roles, entities, and navigation into an ordered design plan.
- Separate information architecture, interaction flows, component/system work, content, and visual design only when their contracts are clear.
- Preserve task completion, exceptional states, permissions, accessibility, responsive behavior, and realistic data states.
- Use prototypes or high-fidelity screens only at the fidelity required by the current acceptance criteria.
- Validate flow completeness before visual polish.

Evidence may include flow coverage, screen/state inventory, interaction annotations, responsive states, accessibility checks, prototype paths, and design-to-requirement traceability.
