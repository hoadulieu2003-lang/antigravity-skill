# AI and data definition

Use this adapter for model-backed features, OCR, retrieval, generation, classification, analytics, or data pipelines.

## Required analysis

- Define the decision or user outcome the AI/data system supports; avoid defining success only as “use a model.”
- Identify sources, ownership, lineage, consent, privacy, retention, expected volume, and known quality limitations.
- Define input/output schemas, pipeline stages, model or prompt boundaries, deterministic components, and human checkpoints.
- Establish evaluation datasets or representative cases, quality metrics, unacceptable failure modes, and baseline comparisons.
- Define uncertainty handling, fallback, escalation, retry, reproducibility, versioning, latency, and cost limits.
- Separate model quality problems from data, orchestration, UI, or policy problems.

## Definition additions

Add data contract, pipeline boundary, evaluation plan, target thresholds, safety and privacy constraints, fallback path, observability needs, and cost/latency budget.
