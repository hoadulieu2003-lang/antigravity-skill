# Product and UI definition

Use this adapter for products whose users complete work through screens or interactive flows.

## Required analysis

- Identify primary and secondary roles, jobs to be done, frequency, urgency, and failure impact.
- Map each proposed capability to a user job or business need. Reject decorative or conventional features with no traceable need.
- Distinguish data entities, functions, navigation destinations, page actions, and quick actions.
- Define critical end-to-end flows, decision points, permissions, exceptional states, and recovery paths.
- Define dashboard questions only when a decision or action follows from the answer.
- Cut MVP by complete operational cycles, not by the smallest feature count.

## Definition additions

Add roles, job-to-capability traceability, information architecture where relevant, critical flows, permission overview, core entities, MVP cut, and screens recommended for later design.

Do not create a menu for actions that belong inside a detail page. Do not design polished UI during Definition unless the user explicitly requests a combined discovery-and-design task.
